# 자체 웹 대시보드 개발 전 사전검증 결과

자체 OLLY 웹 대시보드를 만들기 전에 아래 네 가지를 검증했다.

## 1. Metric이 운영 질문에 답할 수 있는가?

검증 결과: **가능**

Prometheus에서 아래 질문에 답할 수 있다.

### 어떤 기능이 요청을 많이 받는가?

```promql
sum(olly_requests_total) by (feature, status)
```

### 어떤 기능이 토큰을 많이 쓰는가?

```promql
sum(olly_tokens_total) by (feature, token_type)
```

### 어떤 기능이 비용을 많이 쓰는가?

```promql
sum(olly_cost_usd_total) by (feature)
```

## 2. Trace와 metric을 요청 단위로 연결할 수 있는가?

검증 결과: **가능하도록 보강 완료**

API 응답에 `request_id`와 `trace_id`를 함께 반환하도록 수정했다.

응답 예시:

```json
{
  "request_id": "req_b93e8334",
  "trace_id": "a2aa25c7f1488e0e24186443ef7a9e23",
  "model": "gemma3:1b",
  "feature": "chat"
}
```

Prometheus에도 요청 단위 drilldown용 metric을 추가했다.

```promql
olly_request_info_total
```

이 metric에는 아래 label이 들어간다.

```text
request_id
trace_id
model
feature
scenario
status
```

따라서 자체 웹 대시보드는 느린 요청 목록에서 `trace_id`를 이용해 Jaeger trace 상세로 연결할 수 있다.

주의:

`request_id`, `trace_id`는 cardinality가 높은 label이다. MVP와 데모에서는 유용하지만, 운영 환경에서는 최근 N개 요청만 샘플링하거나 별도 저장소에 저장하는 방식이 더 적절하다.

## 3. 로컬 모델 비용 계산 기준이 납득 가능한가?

검증 결과: **가능**

로컬 `gemma3:1b`는 외부 API 토큰 과금이 없다. 그래서 비용을 아래처럼 분리했다.

```text
token_cost_usd = 0
infra_cost_usd = LLM 실행 시간(초) / 3600 * 시간당 장비 비용
```

현재 기본값:

```text
compute_resource = cpu
compute_hourly_usd = 0.05
```

확인된 Prometheus 쿼리:

```promql
sum(olly_infra_cost_usd_total) by (resource, model)
```

```promql
sum(olly_inference_compute_seconds_total) by (resource, model)
```

```promql
sum(olly_token_cost_usd_total)
```

검증 결과 `gemma3:1b`에서는 token cost가 0이고, CPU 실행 시간 기반 infra cost가 증가하는 것을 확인했다.

## 4. 알림이 의미 있게 동작하는가?

검증 결과: **동작 확인**

Prometheus alert rule을 low-traffic MVP에서도 검증 가능하도록 `increase()` 기반으로 조정했다.

확인된 firing alert:

```text
OllyHighP95Latency
OllyErrorRateHigh
OllyTokenUsageSpike
OllyRagRetrieveSlow
OllyLocalInferenceCostSpike
```

알림 규칙 예시:

```promql
histogram_quantile(0.95, sum(increase(olly_request_duration_seconds_bucket[5m])) by (le)) > 3
```

```promql
sum(increase(olly_errors_total[5m])) / clamp_min(sum(increase(olly_requests_total[5m])), 1) > 0.05
```

```promql
histogram_quantile(0.95, sum(increase(olly_stage_duration_seconds_bucket{stage="retrieve"}[5m])) by (le)) > 1.5
```

## 결론

자체 웹 대시보드를 만들기 위한 핵심 전제 네 가지는 확인됐다.

| 검증 항목 | 결과 |
| --- | --- |
| 운영 질문에 답할 metric | 가능 |
| request_id/trace_id 기반 drilldown | 가능 |
| 로컬 모델 비용 계산 | 가능 |
| 알림 동작 | 가능 |

따라서 다음 단계로 자체 OLLY 웹 대시보드를 만들 수 있다.

추천 화면 구조:

```text
상단: 요청 수, 토큰 수, 총 비용, p95 latency, 에러율
중단: 기능별 비용, 모델별 비용, 단계별 병목, 토큰 추이
하단: 최근 요청 목록, trace_id 링크, active alerts
```
