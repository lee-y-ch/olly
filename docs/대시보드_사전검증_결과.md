# OLLY 대시보드 검증 결과

이 문서는 자체 OLLY 웹 대시보드를 만들기 전후로 확인한 내용을 정리한 것이다.

현재는 자체 웹 대시보드가 구현되어 있다.

```text
사용자 챗봇 UI: http://localhost:8001/chat-ui
운영자 대시보드: http://localhost:8001/dashboard
```

## 1. 운영 질문에 답할 metric이 있는가?

검증 결과: **가능**

Prometheus metric으로 아래 질문에 답할 수 있다.

### 어떤 기능이 요청을 많이 받는가?

```promql
sum(olly_requests_total) by (feature, status)
```

### 어떤 기능이 토큰을 많이 쓰는가?

```promql
sum(olly_tokens_total) by (feature, token_type)
```

### 어떤 기능이 비용을 많이 쓰는가?

```promql
sum(olly_cost_usd_total) by (feature)
```

### 어느 단계가 느린가?

```promql
histogram_quantile(0.95, sum(increase(olly_stage_duration_seconds_bucket[5m])) by (stage, le))
```

## 2. 요청 단위로 trace와 metric을 연결할 수 있는가?

검증 결과: **가능**

`POST /chat` 응답에는 `request_id`와 `trace_id`가 포함된다.

응답 예시:

```json
{
  "request_id": "req_6b416a56",
  "trace_id": "581bf5f8a556b3843d3dfa910fc7e02b",
  "model": "gemma3:1b",
  "feature": "chat"
}
```

운영자 대시보드는 Jaeger API를 조회해 최근 `POST /chat` 요청 목록을 만든다.

대시보드에서 요청 하나를 클릭하면 아래 단계를 보여준다.

```text
Retrieve
LLM Generation
Post-process
```

## 3. 로컬 모델 비용 계산 기준이 납득 가능한가?

검증 결과: **가능**

로컬 `gemma3:1b`는 외부 API 토큰 과금이 없다.

그래서 비용을 아래처럼 나눈다.

```text
token_cost_usd = 0
infra_cost_usd = LLM 실행 시간(초) / 3600 * 시간당 장비 비용
```

현재 기본값:

```text
compute_resource = cpu
compute_hourly_usd = 0.05
```

확인 쿼리:

```promql
sum(olly_infra_cost_usd_total) by (resource, model)
```

```promql
sum(olly_inference_compute_seconds_total) by (resource, model)
```

```promql
sum(olly_token_cost_usd_total)
```

## 4. 알림이 의미 있게 동작하는가?

검증 결과: **동작 확인**

Prometheus alert rule은 low-traffic MVP에서도 확인하기 쉽도록 `increase()` 기반으로 작성되어 있다.

주요 alert:

```text
OllyHighP95Latency
OllyErrorRateHigh
OllyTokenUsageSpike
OllyRagRetrieveSlow
OllyLocalInferenceCostSpike
```

예시:

```promql
histogram_quantile(0.95, sum(increase(olly_request_duration_seconds_bucket[5m])) by (le)) > 3
```

```promql
histogram_quantile(0.95, sum(increase(olly_stage_duration_seconds_bucket{stage="retrieve"}[5m])) by (le)) > 1.5
```

## 5. 자체 웹 대시보드에서 확인된 것

`http://localhost:8001/dashboard`에서 아래를 확인할 수 있다.

| 영역 | 확인 내용 |
| --- | --- |
| Avg Latency | 선택한 시간 동안 평균 응답 시간 |
| Total Tokens | 전체 토큰 사용량 |
| Total Cost | 로컬 추론 시간 기반 총 비용 |
| Success Rate | 성공 요청 비율 |
| Recent Requests | 최근 `/chat` 요청 목록 |
| Trace Detail | 요청 하나의 단계별 병목 |
| Cost Analysis | 기능별 비용 |
| Active Alerts | Prometheus alert 상태 |

## 6. 남은 보완점

MVP에서는 충분하지만 실제 운영 서비스로 확장하려면 아래가 필요하다.

- request_id/trace_id를 Prometheus label로 많이 저장하지 않도록 별도 저장소 도입
- 최근 요청 목록을 Jaeger API가 아니라 DB에서 조회
- 사용자/조직별 비용 분리
- Slack/Discord 알림 연동
- 대시보드 인증/권한 관리
- 장기 metric 보관 정책
