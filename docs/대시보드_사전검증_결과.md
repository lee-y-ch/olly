# OLLY 대시보드 사전검증 결과

이 문서는 OLLY 자체 웹 대시보드와 분석 챗봇이 실제 운영 질문에 답할 수 있는지 검증한 결과이다.

현재 구현 화면:

```text
사용자 챗봇 UI: http://localhost:8001/chat-ui
운영자 대시보드: http://localhost:8001/dashboard
```

## 1. metric으로 운영 질문에 답할 수 있는가?

검증 결과: **가능**

Prometheus metric으로 아래 질문에 답할 수 있다.

### 요청 수

```promql
sum(increase(olly_requests_total[1h]))
sum(increase(olly_requests_total[1h])) by (feature, status)
```

### 토큰 사용량

```promql
sum(increase(olly_tokens_total[1h]))
sum(increase(olly_tokens_total[1h])) by (feature)
```

### 비용

```promql
sum(increase(olly_cost_usd_total[1h]))
sum(increase(olly_cost_usd_total[1h])) by (feature)
sum(increase(olly_infra_cost_usd_total[1h])) by (resource, model)
```

### 단계별 병목

```promql
histogram_quantile(
  0.95,
  sum by (stage, le) (increase(olly_stage_duration_seconds_bucket[1h]))
)
```

### 기간 비교

현재 구간:

```promql
sum(increase(olly_cost_usd_total[24h]))
```

이전 구간:

```promql
sum(increase(olly_cost_usd_total[24h] offset 24h))
```

## 2. trace로 요청 하나를 분석할 수 있는가?

검증 결과: **가능**

`POST /chat` 응답에는 `request_id`와 `trace_id`가 포함된다.

운영자 대시보드는 Jaeger API에서 최근 `POST /chat` 요청을 읽고 아래 정보를 만든다.

```text
request_id
trace_id
feature
scenario
model
status
latency_ms
tokens
cost_usd
stage duration
```

Trace Detail에서 확인하는 단계:

```text
retrieve
llm_call
postprocess
```

## 3. 분석 챗봇이 실제 데이터를 읽는가?

검증 결과: **가능**

분석 흐름:

```text
질문
  ↓
analysis_intents.py
  ↓
analysis.py
  ↓
Prometheus/Jaeger 조회
  ↓
근거 수치가 포함된 답변
```

검증한 질문:

```text
현재 상태 요약해줘
어제랑 비교해서 비용이 왜 늘었어?
최근 알림 떠 있어?
모델별 비용 알려줘
운영 랭킹 보여줘
가장 느린 요청 목록 보여줘
방금 요청 왜 느렸어?
토큰 제일 많이 쓰는 기능 뭐야?
```

확인 결과:

- 비용 비교는 현재/이전 구간을 비교한다.
- 알림 질문은 Prometheus alert 상태를 읽는다.
- 모델 질문은 모델별 비용 metric을 읽는다.
- 랭킹 질문은 비용/토큰/stage p95를 정렬한다.
- 요청 질문은 Jaeger recent trace에서 가장 느린 요청과 병목 stage를 찾는다.

## 4. 로컬 모델 비용 계산은 납득 가능한가?

검증 결과: **가능**

현재 `gemma3:1b`는 외부 API 과금이 없다.

```text
token_cost_usd = 0
infra_cost_usd = LLM 실행 시간(초) / 3600 * 시간당 장비 비용
```

확인 쿼리:

```promql
sum(increase(olly_token_cost_usd_total[1h]))
sum(increase(olly_infra_cost_usd_total[1h])) by (resource, model)
sum(increase(olly_inference_compute_seconds_total[1h])) by (resource, model)
```

## 5. 알림은 동작하는가?

검증 결과: **가능**

Prometheus alert rule:

```text
OllyHighP95Latency
OllyErrorRateHigh
OllyTokenUsageSpike
OllyRagRetrieveSlow
OllyLocalInferenceCostSpike
```

확인:

```text
http://localhost:9090/alerts
```

분석 챗봇 질문:

```text
최근 알림 떠 있어?
```

## 6. 자체 웹 대시보드에서 확인되는 것

| 영역 | 확인 내용 |
| --- | --- |
| Avg Latency | 선택 시간 동안 평균 응답 시간 |
| Total Tokens | 전체 토큰 사용량 |
| Total Cost | 로컬 추론 시간 기반 총 비용 |
| Success Rate | 성공 요청 비율 |
| Recent Requests | 최근 `/chat` 요청 |
| Trace Detail | 요청 하나의 단계별 병목 |
| Cost Analysis | 기능별 비용 |
| Active Alerts | Prometheus alert 상태 |

## 7. 남은 보완점

실제 운영 서비스 수준으로 가려면 아래가 필요하다.

- request summary 저장용 DB
- 사용자/조직별 비용 분리
- Slack/Discord 알림 발송
- 장기 보관용 metric/log 저장소
- 대시보드 인증/권한
- 실제 RAG vector DB 연동
- 외부 API 모델별 단가 테이블
