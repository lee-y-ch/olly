# 팀원 4명 병렬 작업 가이드

현재 OLLY는 동작하는 MVP가 있다. 앞으로의 작업은 기존 기능을 깨지 않고, 발표 완성도와 실제 운영 도구 수준을 높이는 방향으로 나눈다.

## 1. 공통 약속

아래 이름은 바꾸지 않는다.

| 항목 | 값 |
| --- | --- |
| 사용자 화면 | `http://localhost:8001/chat-ui` |
| 운영자 화면 | `http://localhost:8001/dashboard` |
| 질문 API | `POST /chat` |
| 로컬 모델 | `gemma3:1b` |
| LLM 백엔드 | `ollama` |
| trace 단계 | `retrieve`, `llm_call`, `postprocess` |
| service name | `olly-sample-api` |
| API 포트 | `8001` |
| Grafana 포트 | `3001` |
| Prometheus 포트 | `9090` |
| Jaeger 포트 | `16686` |

작업 전:

```bash
git pull origin main
```

작업 후 최소 확인:

```bash
docker compose -f deploy/docker-compose.yml up -d --build
curl http://localhost:8001/health
```

## 2. 1번 팀원: API / LLM / 비용 계산

### 책임

`POST /chat` 흐름과 로컬 LLM 호출, 응답 schema, 비용 계산을 관리한다.

### 담당 파일

```text
apps/sample-llm-api/app/main.py
apps/sample-llm-api/app/schemas.py
apps/sample-llm-api/app/ollama_llm.py
apps/sample-llm-api/app/mock_llm.py
apps/sample-llm-api/app/pricing.py
apps/sample-llm-api/app/config.py
```

### 해야 할 일

- `/chat` 응답 필드 안정화
- Ollama 장애/timeout 메시지 개선
- `gemma3:1b` 외 모델 전환 가능성 정리
- token 계산 방식 개선
- CPU/GPU 시간당 비용 설정 정리
- `STABLE_DEMO_ANSWERS` 동작 방식 문서화

### 완료 기준

- 모든 요청이 아래 필드를 반환한다.

```text
request_id, trace_id, answer, model, feature, llm_backend,
input_tokens, output_tokens, cost_usd, token_cost_usd,
infra_cost_usd, compute_seconds, latency_ms, status
```

## 3. 2번 팀원: 관측성 / Metric / Trace

### 책임

서비스 내부 동작을 Prometheus metric과 Jaeger trace로 남긴다.

### 담당 파일

```text
apps/sample-llm-api/app/metrics.py
apps/sample-llm-api/app/telemetry.py
apps/sample-llm-api/app/main.py
observability/otel-collector.yaml
observability/prometheus.yml
observability/alert-rules.yml
```

### 해야 할 일

- `retrieve`, `llm_call`, `postprocess` span 속성 검증
- Prometheus metric label 정리
- 고카디널리티 label 위험성 점검
- alert rule 임계값 조정
- Jaeger에서 trace 검색이 되는지 확인
- Prometheus scrape 오류 확인

### 중요 metric

```text
olly_requests_total
olly_tokens_total
olly_cost_usd_total
olly_token_cost_usd_total
olly_infra_cost_usd_total
olly_inference_compute_seconds_total
olly_request_duration_seconds
olly_stage_duration_seconds
olly_llm_duration_seconds
olly_generation_tokens_per_second
olly_errors_total
```

### 완료 기준

- `/chat-ui`에서 질문을 보내면 Jaeger trace가 생긴다.
- Prometheus에서 주요 metric이 조회된다.
- alert rule이 Prometheus에서 확인된다.

## 4. 3번 팀원: 분석 챗봇 / 대시보드 데이터 API

### 책임

운영 질문을 해석하고 Prometheus/Jaeger 데이터를 읽어 답변하는 분석 기능을 관리한다.

### 담당 파일

```text
apps/sample-llm-api/app/analysis.py
apps/sample-llm-api/app/analysis_intents.py
apps/sample-llm-api/app/analysis_metrics.py
apps/sample-llm-api/app/dashboard.py
```

### 해야 할 일

- 질문 의도 분류 개선
- 기간 파싱 개선: `15m`, `1h`, `6h`, `24h`
- request_id/trace_id 기반 분석 개선
- 비용/토큰/지연/알림/랭킹 답변 추가
- Prometheus 쿼리 실패 시 fallback 메시지 개선
- 분석 답변이 질문 범위를 벗어나지 않는지 확인

### 현재 지원 질문 유형

```text
상태 요약
비용 분석
기간 비교
토큰/비용 랭킹
RAG vs LLM 비교
가장 느린 요청 목록
request_id/trace_id 상세 분석
알림 확인
모델별 비용
```

### 완료 기준

- 예시 문장이 아니어도 비슷한 운영 질문에 답한다.
- 답변은 Prometheus/Jaeger 실제 값에 근거한다.
- 질문이 비용이면 비용만, 토큰이면 토큰만, 병목이면 병목만 답한다.

## 5. 4번 팀원: 프론트엔드 / 문서 / 발표

### 책임

사용자 화면, 운영자 화면, 문서, 발표 흐름을 관리한다.

### 담당 파일

```text
apps/sample-llm-api/app/static/chat_ui.html
apps/sample-llm-api/app/static/dashboard.html
docs/
README.md
```

### 해야 할 일

- `/chat-ui`에서 분석 질문을 쉽게 입력할 수 있게 정리
- `/dashboard` Recent Requests와 Trace Detail 가독성 개선
- 발표 시나리오 정리
- 실행 문서 최신화
- 팀원별 작업 범위 유지
- 화면 깨짐, console error 확인

### 완료 기준

- 새 팀원이 문서만 보고 실행할 수 있다.
- 발표자가 문서만 보고 시연할 수 있다.
- `/chat-ui`와 `/dashboard`의 역할이 명확하다.
